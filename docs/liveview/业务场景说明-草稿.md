## 2. 申请场景

- 申请场景类型：**进度（PROGRESS）**
- 场景描述关键词：用户主动发起的本地媒体处理任务实时进度（视频转码、格式导出、GIF 转换、无损合并、音轨替换、字幕封装等）。

## 3. 业务场景概述

MediaBox 是一款本地媒体处理工具箱。用户在应用内选定媒体文件并主动点击「开始 / 导出」后，应用在后台执行媒体处理任务，并通过实况窗实时展示该任务的执行进度，直至任务完成或被终止。

该业务满足实况窗全部基础约束：

1. **时段性**：单个媒体处理任务通常持续数十秒至数十分钟，有明确的开始（用户点击开始）与结束（任务完成 / 失败 / 用户取消）。应用侧保证单个实况窗生命周期不超过 8 小时。
2. **时效性**：实况窗展示的正是「正在进行中」的处理任务的实时状态。
3. **变化性**：处理进度（已处理字节数 / 总字节数、阶段状态）持续动态刷新；应用侧节流为至少每 1 秒更新一次，远低于系统流控上限。
4. **触发要求**：实况窗仅在用户主动点击「开始 / 导出」等操作后创建；不存在任何后台静默自动生成的实况窗。用户对进度展示有明确预期。
5. **价值约束**：仅展示任务进度信息（任务名、阶段、百分比、预计剩余时间），不包含任何营销推广、广告宣传或运营活动内容。

## 4. 触发方式与用户预期

- 触发入口：工作台页（文件驱动工作台）与批量任务页，用户选择处理参数后点击「开始」。
- 用户预期：用户发起耗时处理后可能切出应用（回桌面、锁屏），实况窗使其无需重新打开应用即可掌握处理进度。
- 结束事件：任务完成 → 展示「已完成」短暂时长（约 5 秒，keepTime ≤ 300 秒）后结束；任务失败或用户主动取消 → 立即结束实况窗。每个任务同一时间仅存在一个实况窗。

## 5. 实况窗状态节点

| 节点 | 触发时机 | 胶囊态 | 卡片态 | 更新方式 |
| --- | --- | --- | --- | --- |
| 创建 | 用户点击开始，任务进入执行 | 文本胶囊：「处理中」 | 进度模板：任务名 + 0% | startLiveView |
| 处理中 | 进度变化（≥1 秒节流） | 进度胶囊：已处理量 / 总量 | 进度模板：任务名 + 百分比 + 阶段文案 | updateLiveView |
| 已完成 | 任务处理成功 | 「完成」 | 进度模板：100% / 已完成 | updateLiveView → 数秒后 stopLiveView |
| 失败 / 取消 | 任务失败或用户取消 | — | — | stopLiveView 立即结束 |

- 卡片点击动作：拉起应用任务队列页（wantAgent 指向 TasksPage）。
- 失败与取消属于异常分支，实况窗立即结束，不留营销或挽留类内容。

## 6. 技术方案

- 使用 LiveView Kit（`@kit.LiveViewKit`）端侧本地接口：`liveViewManager.startLiveView / updateLiveView / stopLiveView`。
- `event` 取值：PROGRESS；卡片布局使用系统 `LAYOUT_TYPE_PROGRESS` 进度可视化模板（节点 2–5 个：解析 → 处理 → 完成）。
- 更新频率：≥1 秒 / 次（应用内节流），符合系统流控（创建 ≤10 次/秒、更新 ≤20 次/秒）。
- 用户未开启实况窗开关或应用未获准入时，功能无声降级为应用内任务队列页展示，不影响核心功能。
- 长任务保障：批量任务串行执行，每个任务对应独立实况窗并独立结束；任何实况窗存活时间不超过 8 小时上限。

## 7. 内容文案示例（符合设计规范字数）

- 胶囊主文本（1–3 字）：「处理中」「已完成」
- 胶囊副文本（1–6 字）：「转码 45%」「合并中」
- 卡片主标题（≤16 字）：「正在转码 summer_trip.mp4」
- 卡片副标题（≤19 字）：「剩余约 3 分钟 · HEVC 1080p」
- 展示内容不含用户隐私信息、不含营销文案。

## 8. 开发者承诺

1. 仅在获批业务场景（PROGRESS 进度场景，即用户主动发起的媒体处理任务进度展示）范围内使用实况窗开放能力。
2. 实况窗展示内容严格遵守《实况窗设计规范》与文案规范，随系统版本更新持续适配。
3. 不将实况窗用于营销推广、广告宣传、活动预热；不展示用户隐私信息。
4. 同一业务事件同一时间仅创建一个实况窗，且保证每个实况窗有明确的结束事件；单个实况窗生命周期不超过 8 小时。
5. 如违反上述承诺及华为相关规范，接受华为收回准入资格及应用下架等管控措施。
